# Revue sécurité, vie privée et robustesse — Learning English with Kai

- **Revue faite par** : Ani (DevOps / sécurité), à la demande du PO, le 29/10/2026
- **Version revue** : `main` @ `51efca8` (« Version du 16 octobre 2026 » selon le README)
- **Méthode** : lecture seule, recherches ciblées dans `index.html` (3 684 lignes, 1,7 Mo, certaines lignes font 379 Ko),
  inventaire des fichiers, recherche de secrets sur tout le dépôt. L'application n'a **pas** été modifiée.
- **Contexte qui compte** : l'utilisateur est **un enfant mineur** (6e). Toute donnée qui sort de l'appareil
  (voix, adresse IP, prénom) se juge avec ce filtre (RGPD : en France, accord parental requis sous 15 ans).

## 1. Sécurité et vie privée

### I-1 (importante) — La voix de l'enfant est envoyée aux serveurs du navigateur, contrairement à ce que dit le README

- **Preuve** : `index.html:2615` `const TK_SR=window.SpeechRecognition||window.webkitSpeechRecognition` puis
  `index.html:2636` `new TK_SR(); … r.lang="en-GB"`. Dans Chrome, cette API envoie l'enregistrement audio aux
  serveurs de Google pour le transcrire (Edge : Microsoft, Safari : Apple). Le README dit : « la phrase est vérifiée
  par des règles de grammaire intégrées à l'application, **sans rien envoyer** ». C'est vrai pour la vérification
  de grammaire, **faux pour la voix**.
- **Risque** : enregistrement vocal d'un mineur transmis à un tiers sans information du parent.
- **Correction** : (a) corriger la phrase du README ; (b) afficher avant le premier usage du micro un message
  « Ta voix est envoyée à Google/Microsoft pour être transformée en texte. Demande à un parent. » avec un bouton
  « Taper ma phrase à la place » ; (c) option à étudier : la reconnaissance **sur l'appareil** proposée par les
  versions récentes de Chrome (`processLocally`), à vérifier sur le parc réel.
- **Effort** : (a) 5 min, (b) 1 h, (c) une demi-journée de test.

### I-2 (importante) — Google Fonts : l'adresse IP de l'enfant part chez Google à chaque ouverture

- **Preuve** : `index.html:15-17`
  `<link href="https://fonts.googleapis.com/css2?family=Roboto+Condensed…">` et `…family=Noto+Emoji…&display=block`.
- **Risque** : transfert de l'IP et du navigateur à Google sans consentement (jugé contraire au RGPD : tribunal de
  Munich, 20/01/2022). Effet de bord : avec `display=block`, sans réseau le texte des émojis reste invisible
  jusqu'à 3 s.
- **Correction** : télécharger une fois les fichiers `.woff2` dans un dossier `fonts/` et remplacer les trois
  balises `<link>` par un `@font-face` local (ou utiliser une police système).
- **Effort** : 1 h.

### I-3 (importante) — Le code parent est stocké en clair

- **Preuve** : `index.html:3037` `const PCK="kai.pcode",pcode=()=>localStorage.getItem(PCK)` ;
  `index.html:3047` `localStorage.setItem(PCK,a)` ; vérification `if(v===c)` (`index.html:3041`).
- **Risque** : n'importe qui sur l'ordinateur lit le code en 10 secondes (F12 › Application › Local Storage).
  Beaucoup de parents réutilisent un code de carte bancaire ou de téléphone : c'est **ce** code qui fuit.
  Limite à écrire noir sur blanc : sans serveur, un enfant débrouillard peut aussi **effacer** la clé et contourner
  le contrôle. Le code parent est un garde-fou contre l'erreur, pas un verrou.
- **Correction** : stocker une empreinte salée (`crypto.subtle`, PBKDF2 ou au minimum SHA-256 + sel aléatoire)
  au lieu du code ; ajouter sous le champ « N'utilisez pas le code de votre carte ou de votre téléphone ».
  Prévoir la migration : si `kai.pcode` contient encore 4–8 chiffres, le hacher au premier usage.
- **Effort** : 1 h.

### I-4 (importante) — L'adresse e-mail personnelle du PO est publique dans l'historique

- **Preuve** : `git log -1 --format='%ae'` sur `main` renvoie une adresse personnelle (non recopiée ici).
  Chaque « Add files via upload » l'expose sur un dépôt public.
- **Risque** : collecte par des robots (spam, hameçonnage ciblé).
- **Correction** : GitHub › Settings › Emails › cocher « Keep my email addresses private » et « Block command line
  pushes that expose my email ». Le script `publier.ps1` utilise l'adresse `…@users.noreply.github.com`.
  Les anciens commits restent tels quels (les réécrire = `push --force` sur `main`, déconseillé).
- **Effort** : 5 min.

### M-1 (mineure) — Pas de Content-Security-Policy

- **Preuve** : 0 occurrence de `Content-Security-Policy` dans `index.html`.
- **Risque** : faible aujourd'hui (l'échappement est fait), mais rien n'empêcherait un futur bug d'injection
  d'envoyer des données ailleurs.
- **Correction** : après I-2, ajouter dans `<head>` :
  `<meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self' 'unsafe-inline'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; media-src 'self' data: blob:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'">`
  puis tester toutes les pages (voix, micro, sauvegarde).
- **Effort** : 1 h avec les tests.

### M-2 (mineure) — L'import d'une sauvegarde accepte trop de choses

- **Preuve** : `kaiMerge` (`index.html:3024-3032`) recopie **toute** clé commençant par `kai.` absente de l'appareil
  (`if(localStorage.getItem(k)===null)localStorage.setItem(k,v)`) et ajoute les profils tels quels ; aucune limite
  de taille du fichier (`kaiImport`, `index.html:3033`).
- **Risque** : un fichier « sauvegarde » piégé ou énorme (envoyé par un camarade) peut remplir le stockage ou
  injecter des valeurs inattendues. L'affichage est échappé, donc pas d'exécution de code constatée.
- **Correction** : liste blanche des préfixes de clés connus, contrôle des types (`p.id`, `p.name` chaînes courtes),
  refus au-delà de 5 Mo.
- **Effort** : 1 h.

### M-3 (mineure) — `esc()` n'échappe pas l'apostrophe

- **Preuve** : `index.html:1181` `replace(/[&<>"]/g, …)`.
- **Risque** : nul tant que tous les attributs HTML sont entre guillemets doubles ; piège pour une future évolution.
- **Correction** : ajouter `'` → `&#39;`. **Effort** : 5 min.

### M-4 (mineure, pour information) — Code prévu pour les « artefacts Claude »

- **Preuve** : `index.html:1398` (`window.claude.use("db")`), `2914` (`use("sample")`), `3019` (`use("downloads")`).
- **Risque** : sur GitHub Pages, `window.claude` n'existe pas : ce code ne fait rien. Si la même page est ouverte
  comme artefact Claude, le prénom et la progression sont synchronisés côté plateforme et les phrases de l'élève
  sont envoyées au modèle. À savoir avant de partager l'artefact.
- **Correction** : rien d'obligatoire ; le mentionner dans le README. **Effort** : 5 min.

### Ce que contient le stockage du navigateur (`localStorage`)

Clés `kai.*` : `kai.profiles.v1` (prénoms et niveaux des élèves), `kai.daily.v1.<id>` (travail du jour),
`kai.qsave.*`, `kai.tsave.*`, `kai.t6.*`, `kai.tq.*`, `kai.pq.*`, `kai.diy.*` (progression, tests, quiz),
`kai.rec`, `kai.voice`, `kai.rate`, `kai.qnum` (réglages), `kai.kv` (cache des voix), **`kai.pcode` (code parent en
clair, voir I-3)**. Rien n'est envoyé au réseau. Le fichier de sauvegarde `kai-english-AAAA-MM-JJ.json` contient
tout sauf `kai.pcode` et `kai.kv` : il contient les prénoms, il ne doit **jamais** être déposé dans le dépôt
(le `.gitignore` et `publier.ps1` le bloquent).

## 2. Robustesse

### I-5 (importante) — Un seul fichier de 1,7 Mo, avec des lignes de 379 Ko

- **Preuve** : `index.html` = 1 762 665 octets, 3 684 lignes, la plus longue fait 379 185 caractères
  (les listes de mots et d'exercices sont en ligne).
- **Risque** : impossible de relire ce qui change d'une version à l'autre (une virgule modifiée = une ligne de
  379 Ko « différente ») ; une régression passe inaperçue. Côté réseau, c'est acceptable : ~494 Ko compressé.
- **Correction** : sortir les données (mots, exercices, leçons) dans des fichiers `data/*.js` chargés par
  `<script src>`, une entrée par ligne. Pas urgent, à faire lors d'une prochaine grosse évolution.
- **Effort** : 1 à 2 jours.

### M-5 (mineure) — PWA sans service worker

- **Preuve** : `manifest.webmanifest` valide, 0 occurrence de `serviceWorker`.
- **Conséquence** : l'app s'installe sur l'écran d'accueil mais **ne marche pas hors ligne**. Avantage : aucun
  problème de vieille version coincée en cache. GitHub Pages met en cache ~10 min : une nouvelle version est vue
  au plus tard 10 min après publication (ou tout de suite avec Ctrl+F5).
- **Correction** : rien si le hors-ligne n'est pas un besoin. Sinon, un service worker **versionné** (nom de cache
  = date de version) ; effort une demi-journée.

### M-6 (mineure) — Voix : 7,8 Mo de MP3 encodés en base64 dans du JSON

- **Preuve** : `du -sh voice` = 7,8 Mo, 4 fichiers de 1,5 à 2,3 Mo (`{"404d0b61960a":"SUQzBAAA…"}`).
- **Conséquence** : +33 % de poids dû au base64, et chaque fichier est téléchargé **en entier** avant la première
  phrase (lent sur une connexion faible). Bon point : chargement à la demande.
- **Correction** : fichiers `.mp3` (ou `.opus`) individuels. **Effort** : une demi-journée.

### M-7 (mineure) — Icônes lourdes

- **Preuve** : `icon-512.png` 271 Ko, `icon-maskable-512.png` 201 Ko. `img/` (99 webp, 1,6 Mo) est bien optimisé.
- **Correction** : recompresser les PNG (objectif < 60 Ko chacune). **Effort** : 10 min.

### M-8 (mineure) — Fichier `download` vide à la racine

- **Preuve** : `download` fait 0 octet et n'est référencé nulle part ; sans doute un reste du glisser-déposer.
- **Correction** : le supprimer (non fait ici : revue en lecture seule). **Effort** : 1 min.

## 4. Chaîne de livraison (ajoutée par cette PR)

Avant : glisser-déposer sur github.com, Pages publie la branche `main` telle quelle, **sans aucun contrôle**.
Après : `.github/workflows/publier-site.yml` + `.github/verifier.py`.

| Étape | Ce qui se passe | Garde-fou |
|---|---|---|
| Envoi | `publier.bat` (PC), édition sur github.com (téléphone) ou GitHub Desktop | `publier.ps1` bloque clés, `.env`, sauvegardes d'élèves, fichiers > 50 Mo **avant** l'envoi |
| Vérification | secrets, sauvegardes d'élèves, manifest + icônes, liens `img/` `voice/` de `index.html`, JSON des voix, taille | échec = **site inchangé**, croix rouge, e-mail |
| Publication | copie des seuls fichiers de l'app (pas `docs/`, scripts, guide, README) → `actions/deploy-pages` | environnement `github-pages` limité à `main` |
| Version | `version.json` + `<meta name="version">` dans la copie publiée, étiquette `vAAAA.MM.JJ.N` | le code source de l'app n'est pas modifié |

Choix de sécurité : permissions à zéro par défaut, chaque tâche ne reçoit que ce qu'il lui faut (`pages: write`
pour publier, `contents: write` seulement pour poser l'étiquette) ; actions officielles GitHub uniquement,
**épinglées par empreinte** (`upload-pages-artifact` v5.0.0, `deploy-pages` v5.0.1) ; code récupéré avec `git`,
contrôles en Python standard (aucune dépendance installée). Coût : gratuit sur un dépôt public, environ 1 min par
publication. Pas d'aperçu visuel des pull requests (GitHub Pages = un seul site par dépôt) : la PR est vérifiée,
pas publiée.

### I-6 (importante) — Le compte GitHub est désormais la seule clé du site

- **Constat** : quiconque prend la main sur le compte `colouis-web` publie ce qu'il veut sur un site utilisé par
  un enfant (y compris un script qui lit le `localStorage`). C'était déjà vrai avant ; le téléphone devient un
  nouveau point d'entrée.
- **Preuve** : non vérifiable depuis le dépôt (réglage du compte).
- **Correction** : activer la double authentification (Settings › Password and authentication › 2FA, avec
  l'application d'authentification ou une clé d'accès) ; ne pas ajouter de collaborateurs sans besoin.
- **Effort** : 10 min.

### Limites honnêtes des contrôles automatiques

- Ils repèrent les formats de clés **connus** ; une clé d'un format inconnu passerait.
- Avec GitHub Desktop ou github.com, un fichier sensible est bloqué **à la publication du site**, mais il est
  déjà dans le dépôt public : il faut alors le retirer **et** révoquer la clé.
- Ils ne testent pas le fonctionnement de l'app (pas de test automatique de l'interface).
